🤖 我用 Claude Code + MiMo + Hermes 三件套搭博客：真实体验 + 踩坑总结

发表于2026-06-15|更新于2026-06-15|AI 工具经验总结
|浏览量:

🎯 为什么要写这篇

搭建这个博客的过程中，我同时在用三个 AI 工具：

  • Claude Code（Anthropic 官方 CLI）
  • MiMo Code（小米开源）
  • Hermes Agent（NousResearch 多模态助手）

不是炫技，是真的遇到了不同的活儿。这篇文章把它们放在一起做个真实横评——谁擅长什么，谁掉链子，什么时候该切换。

背景：我编程算新手，会 Python 基础语法，但完全不懂前端。博客是用 AI 边问边搭的。

🧰 三件套速览

工具 类型 核心定位 我的使用场景
Claude Code 命令行 AI 编程 复杂任务分步执行 写 Hexo 配置、调 layout 模板
MiMo Code 终端原生 AI 编程 跨会话记忆 重复性改文件、批量操作
Hermes Agent 多模态 AI 助手 通用对话 + 桌面端 调研、写文章、生成配图建议

🤖 Claude Code：稳，但贵

✅ 干得好的活

1. 复杂的 hexo 配置（最常用）
我让 Claude Code 帮我把 4 篇打字网站教程底部加”系列导航”。它：

  • 准确找到 _config.yml 里的 post_pagination 配置
  • 读懂我给的 4 个文件路径
  • 按序号生成 4 个不同的底部卡片
  • 顺手提醒”小心 YAML 缩进”
  • 最后跑 hexo clean && hexo deploy 一气呵成

2. 多步调试

我的 bridge_server.py 报 CORS 错，Claude Code 一句句追：

  • 先读代码
  • 找到问题（CORS header 写在 OPTIONS 响应里但 do_POST 没继承）
  • 给修复方案
  • 解释为什么
  • 跑测试验证

❌ 掉链子的时候

1. 贵
Anthropic API 收费，复杂任务动辄 1-2 美元一次。我写这个博客期间 API 账单大概 8 美元——不贵，但和免费工具比是数量级差距。

2. 沙箱限制
跑 hexo deploy 时它会”看不到”我的 GitHub 凭据，得我手动复制粘贴。最后一步 git push 永远得我自己跑。

3. 启动慢
冷启动要 3-5 秒，对短小任务来说”启动开销 > 任务时间”。

🏷️ 一句话总结

“重型武器”——复杂任务值这个价，简单任务杀鸡用牛刀。

🐼 MiMo Code：记忆是王炸

✅ 干得好的活

1. 批量改 frontmatter
11 篇文章的 categories 重组（21 个 → 5 个），MiMo Code 干得漂亮：

  • 读 _config.yml 旧结构
  • 列出 11 篇文章的现状
  • 让我确认新分类
  • 批量改文件 + 备份 + 部署一次跑完

关键加分项：它自动备份 source/_posts.bak.categories，这种”防呆”细节说明它有”做过项目”的经验。

2. 文件级修改的”上下文管理”

❌ 掉链子的时候

1. TUI 学习曲线
第一次打开时全键盘操作，需要学快捷键。习惯了没事，新手会懵。

2. 中文社区还在建设
报错信息偶有英文，解决方案得自己 Google。

3. 任务被”压缩”
有时候它会自作主张跳过一些步骤（比如我让”先备份再改”，它改了但没备份）。需要严格 prompt 约束。

🏷️ 一句话总结

“适合重度多文件操作”——它的记忆让你像在跟一个”记得你项目的人”合作。

🦅 Hermes Agent：通用但深度一般

✅ 干得好的活

1. 调研 + 写文章
我让 Hermes Agent 调研”Vite 5 vs Webpack 5 性能对比”，它 5 分钟给我一份带数据、带表格、带结论的草稿。我只需改改语气、删掉一些”AI 八股”段落就发了。

2. 桌面端操作
Hermes Agent 的桌面客户端比 CLI 友好太多。写文章、查资料、生成配图建议——一个窗口搞定。

3. 多模态
发张截图给它，它能直接读懂。我截了 GitHub 报错，它给我定位到第 17 行的 tagCloud-link 样式冲突。

❌ 掉链子的时候

1. 不擅长”动手改文件”
让它”帮我修改 _config.yml 的某行”——它会输出完整新文件，让你手动复制覆盖。这和 Claude Code 直接 Edit 工具的体验差一截。

2. 长任务容易”失忆”
超过 10 轮的对话，它会忘记前面说的某个约束。得用”总结—重申”的方式不断校正。

3. 通用 = 不专精
写代码不如 Claude Code，批量改文件不如 MiMo，做”广度可以、深度一般”的活儿最合适。

🏷️ 一句话总结

“瑞士军刀”——什么都干一点，但不是任何场景的最优解。

💡 我的”AI 三件套工作流”

实际搭这个博客时我是这么分工的：

3 个工具 7 天搭出博客——按传统方式我可能需要 2 个月。

🪤 7 天里踩过的 5 个坑

1. Claude Code 沙箱看不见我的 GitHub 凭据
每次 deploy 完最后一步 git push 都要我手动跑。解法：让它生成完整命令，复制到 PowerShell 跑。

2. MiMo Code 偶尔”自作主张”跳过备份
prompt 里必须显式写”先备份再改文件”，光说”小心点”它不当回事。

3. Hermes Agent 输出的是”完整新文件”不是 diff
覆盖前必须 diff 看一眼，不然容易丢旧内容。养成习惯：永远先备份再粘贴。

4. 三个工具都不擅长”PR review”
改完一堆文件后，让它们”检查改动”——经常漏看。最终人工 review 不可省。

5. 不同工具有不同的”上下文格式”
MiMo Code 认 MEMORY.md、Claude Code 认 CLAUDE.md、Hermes Agent 认自己的 knowledge base。多工具协作 = 多份记忆。

🎯 什么场景该选谁？

场景 选 为什么
写一个新功能，从 0 到 1 Claude Code 思考深度最强
改一个 bug Claude Code 调试最专业
批量改 10 个文件的某个字段 MiMo Code 记忆 + 多文件无敌
重构分类、整理标签 MiMo Code 它擅长”重组”
调研一个新技术、写文章 Hermes Agent 友好 + 桌面端 + 多模态
配图建议、博客排版 Hermes Agent 视觉理解强
复杂多步任务（涉及多工具） Claude Code 分步执行 + 验证最强
我就是想要个聊天伙伴 Hermes Agent 对话最自然

📝 写给同样想用 AI 搭博客的人

如果你只能选一个：Claude Code。它最专业、文档最全、调试最强。

如果你能选两个：Claude Code + Hermes Agent。一个干活，一个聊天，互补。

如果你能选三个：加上 MiMo Code。当你有”跨会话的多文件任务”时，它会展现真本事。

如果你完全不写代码：Hermes Agent 优先。它最像”和一个人对话”。

🚀 我接下来的计划

  • 主要：Claude Code（生产任务）
  • 辅助：MiMo Code（跨天的大任务）
  • 灵感：Hermes Agent（调研、写文章）
  • 不混用同一项目：避免记忆冲突

这套”3 件套分工“的工作流，我会在后续博客里继续更新——踩新坑、写新案例。

如果你也在用 AI 搭项目，欢迎在评论区告诉我你的工具组合！
